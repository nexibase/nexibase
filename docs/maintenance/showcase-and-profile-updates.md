# 쇼케이스·모바일 메뉴·프로필 이미지 업데이트

쇼케이스 갤러리, 홈페이지 노출 위젯, 모바일 바로가기와 게시글 작성자 이미지 오류 처리는 공식 코어 소스에 포함된다. 게시판 이름은 `쇼케이스`를 유지하며 `/boards/showcase` 경로를 사용한다.

## 기능

- 쇼케이스 게시판의 갤러리 목록은 스크린샷, 소개, 작성자·조회·댓글 수와 사이트 방문 링크를 표시한다. PC에서는 여러 열, 모바일에서는 한 열로 배치한다. 일반 게시판의 목록 방식은 유지한다.
- `showcase-sites` 위젯은 공개 사례 최대 6개를 홈페이지에 표시한다. 서버 초기 데이터와 공개 API는 같은 필드·권한 기준을 사용한다. 비활성·회원 전용 게시판과 비밀글·공지글·비공개 게시글은 홈페이지에 노출하지 않는다.
- 쇼케이스 메뉴가 활성화되어 있으면 모바일 헤더에서도 바로 이동할 수 있다. 저장된 메뉴 이름·대상·접근 권한을 따르며 데스크톱에 중복 표시하지 않는다.
- 작성자 이미지가 정상 로드되면 저장된 프로필 이미지를 보여준다. 이미지가 없거나 로드에 실패하면 공용 Avatar 대체 표시를 사용해 깨진 이미지가 남지 않게 한다.

## 기존 사이트 업데이트

1. 기존 DB와 업로드를 백업한다. 기존 메뉴·위젯·게시글과 프로필 이미지는 사이트 데이터다.
2. 최신 소스를 적용하고 서브모듈과 의존성을 갱신한다. 마이그레이션·테스트·타입 검사·빌드를 실행한다. 업데이트에 설치 초기화나 기본 시드 재실행을 사용하지 않는다.
3. 새 배포 디렉터리의 `public/uploads`를 기존 공용 업로드 경로에 연결한다. DB의 `users.image`가 가리키는 실제 파일도 같은 주소로 제공해야 한다. 관리자 로고를 별도 프로필 이미지로 사용한 사이트도 이 방식으로 유지한다. 사이트별 이미지나 운영 DB 덤프를 저장소에 커밋하지 않는다.
4. 갤러리 설정, 상단 쇼케이스 메뉴, 홈페이지 `showcase-sites` 위젯 구성을 유지한다. 새 설치에서 사용하려면 관리자에서 slug가 `showcase`인 게시판을 만들고 갤러리 방식으로 지정한 뒤 메뉴와 위젯을 추가한다. 다른 사이트에 이 구성을 강제로 생성하지 않는다.
5. 운영 전환 후 PC·모바일 목록과 바로가기, 홈페이지 카드, 정상·잘못된 이미지 주소의 작성자 표시를 확인한다.

공유 데모를 초기화하는 사이트는 DB 구조를 갱신한 초기화 스냅샷도 유지해야 한다. 과거 스냅샷을 복원해 메뉴·프로필·위젯 수정이나 최신 마이그레이션 이력을 되돌리지 않도록 한다.

## 회귀 검사

- 소개·이미지·외부 링크 추출은 HTML 정리와 URL 검증 테스트로 확인한다.
- 모바일 메뉴는 공개·회원·관리자 권한 및 비활성 메뉴, 사용자 지정 이름·대상을 테스트한다.
- 플러그인을 반복 스캔해도 코어 페이지·쇼케이스 API·헤더·카드·작성자 이미지 처리가 유지되고 `showcase-sites` 위젯이 등록되는지 확인한다. `showcase` 경로를 차지하려는 플러그인은 거절한다.
- GitHub Actions는 빈 DB 마이그레이션, 전체 테스트, 타입 검사와 프로덕션 빌드를 실행한다. 쿠키 동의 기능 재도입 검사도 유지한다.
