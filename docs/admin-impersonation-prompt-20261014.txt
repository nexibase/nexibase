NexiBase에서 관리자 사칭을 방지하도록 닉네임 검증과 공식 관리자 표시를 수정해줘.

1. 닉네임 금지 규칙
- 닉네임 어느 위치에든 “관리”, “운영”, “admin”이 포함되면 사용을 금지한다.
- 영문은 대소문자를 구분하지 않는다.
- 예: 관리자, 관리팀, 운영자, 운영진, 사이트운영, admin, Admin, ADMIN, SuperAdmin, administrator는 모두 금지한다.
- 관리자 계정에도 동일한 닉네임 규칙을 적용한다.
- 이 규칙은 닉네임에만 적용한다. 이메일, 로그인 ID, 소개글에는 적용하지 않는다.

2. 변형을 통한 우회 방지
- 검사용 문자열에 Unicode NFKC 정규화를 적용한다.
- 공백과 보이지 않는 문자(제로폭 문자 등)를 제거하고 영문을 소문자로 변환한 뒤 검사한다.
- “관 리자”, “운 영팀”, “a d m i n”, “ＡＤＭＩＮ”도 금지한다.
- 정규화는 검사 목적으로 사용하고, 정상 닉네임의 저장·표시 형식을 임의로 바꾸지 않는다.

3. 모든 닉네임 저장 경로에 적용
- 공통 검증 함수를 만들어 서버에서 반드시 실행한다.
- 회원가입, 프로필 수정, 소셜 로그인 후 닉네임 설정, 닉네임 중복 확인, 관리자 회원 수정 등 실제 닉네임을 저장하는 모든 경로에 적용한다.
- 프런트엔드에서도 같은 규칙으로 안내하되, API를 직접 호출해도 우회할 수 없게 한다.
- 검증 실패 시 DB에 저장하지 않고 다음 메시지를 표시한다.
  “닉네임에는 ‘관리’, ‘운영’, ‘admin’을 포함할 수 없습니다.”
- 입력 화면에도 금지 규칙을 미리 안내한다.

4. 실제 관리자 배지
- 실제 관리자 이름 옆에 방패 아이콘과 “관리자” 배지를 표시한다.
- 배지는 서버가 확인한 계정 권한으로만 결정한다.
- 닉네임, 사용자 입력, 클라이언트가 전달한 권한 값으로 결정하지 않는다.
- 게시글, 댓글, 프로필, 쪽지, 회원 검색 등 닉네임이 표시되는 화면에 일관되게 적용한다.
- 색상뿐 아니라 아이콘과 글자를 함께 사용한다.
- 배지 설명은 “사이트에서 확인한 관리자 계정입니다.”로 한다.
- 기존 권한 체계에서 일반 회원과 게시판 담당자 등을 사이트 관리자로 잘못 표시하지 않는다.

5. 기존 사용자 처리
- 금지 문자열이 포함된 기존 닉네임을 조사한다.
- 기존 계정을 삭제하거나 닉네임을 일괄 변경하지 않는다.
- 관리자 화면에서 해당 계정을 확인할 수 있게 하고, 이후 닉네임을 변경할 때는 새 규칙을 적용한다.
- 배지는 기존 닉네임과 관계없이 실제 관리자 권한에 따라 표시한다.

6. 검증 및 완료 보고
- 정상 닉네임이 계속 사용 가능한지 확인한다.
- 부분 문자열, 영문 대소문자, 전각 문자, 공백, 보이지 않는 문자 변형의 차단을 검증한다.
- API 직접 호출로도 금지 닉네임을 저장할 수 없는지 확인한다.
- 일반 사용자가 관리자 배지를 조작할 수 없는지 확인한다.
- 기존 로그인과 소셜 로그인 흐름이 정상인지 확인한다.
- 변경 파일, 기존 금지 닉네임 계정 수, 검증 결과를 보고한다.
- nexibase.com과 demo.nexibase.com의 운영 구조를 확인하고 두 사이트에 적용한다.
- 기존 데이터와 업로드 파일을 보존하고, 운영 반영 전에 변경 부분을 백업한다.
