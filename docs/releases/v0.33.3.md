# v0.33.3 — 실제 관리자 닉네임 금칙어 예외 허용

실제 관리자도 프로필 닉네임에 `관리`, `운영`, `admin`을 사용할 수 없던 문제를 수정했습니다.

## 변경 내용

- 활성 상태이며 삭제되지 않은 관리자에게만 닉네임 금칙어 예외를 허용합니다. 기존 `isOfficialAdmin` 판별 기준을 사용합니다.
- 저장 API는 매 요청마다 현재 DB 사용자의 권한을 확인합니다. 요청 본문에 관리자 권한 값을 위조해 넣어도 예외가 적용되지 않습니다.
- 프로필 편집 화면에서도 관리자 예외를 적용하고, 관리자에게는 금칙어 제한 안내를 숨깁니다. 저장 후에도 예외 상태가 유지됩니다.
- 일반 회원의 사칭 방지 제한과 닉네임 필수 입력, 길이, 허용 문자 및 중복 검사는 유지합니다. 회원가입과 OAuth 닉네임 검증의 기본 제한도 유지합니다.
- 인증 설정을 `src/lib/auth-options.ts`로 옮겨 Next.js 라우트 타입 검사로 프로덕션 빌드가 중단되던 문제를 수정했습니다. 인증 방식과 설정 값은 유지합니다.

관련 변경: [PR #39](https://github.com/nexibase/nexibase/pull/39).

## 업데이트 안내

v0.33.2에서 패치 업데이트하며 추가 DB 마이그레이션이나 데이터 초기화는 없습니다. Shop은 v1.3.2를 유지합니다.

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
npm ci
npm run typecheck
npm run build
# 사용 중인 배포 방식에 따라 애플리케이션을 재시작합니다.
```

## 검증

- 자동 테스트 97개와 전체 TypeScript 검사를 통과했습니다.
- 비활성·삭제된 관리자, 프로필 조회 후 권한 회수, 요청 권한 위조, 잘못된 입력과 중복 닉네임에 대한 회귀 테스트를 추가했습니다.
- YEOK 프로덕션 빌드 및 실제 API에서 관리자 허용·일반 회원 차단을 확인했습니다.

ESLint는 기존 설정에서 React 설정을 불러오는 중 발생하는 순환 JSON 오류로 실행하지 못했습니다.
