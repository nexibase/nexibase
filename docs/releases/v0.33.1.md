# v0.33.1 — 초기 설정과 플러그인 타입 오류 수정

초기 데이터 설정과 플러그인의 오래된 모델·타입 참조를 수정하고 빌드의 TypeScript 검사를 복구합니다.

## 변경 내용

- 제거된 경매 모델을 참조하던 `prisma/seed-auction.ts`를 코어에서 정리했습니다. 경매 테스트 데이터는 해당 선택 플러그인에서 관리하며, 이전 스크립트는 Git 기록에 보존됩니다.
- 메뉴 초기 설정과 플러그인 활성화가 현재 `WidgetPage`·`PageWidget` 모델을 사용합니다. 홈 페이지의 누락된 위젯만 추가하고, 기존 레이아웃·설정과 다른 페이지의 위젯은 보존합니다. 초기 메뉴·위젯 쓰기는 트랜잭션으로 처리합니다.
- 초기 홈 위젯은 현재 설치기의 언어별 기본값을 재사용합니다. 새 메뉴 초기화에서 제거된 경매 메뉴를 제외하고 FAQ 링크를 `/faqs`로 맞췄습니다.
- 설치 초기화 도구도 현재 페이지·위젯 모델로 수정했습니다. production 실행 차단과 명시적 확인 가드는 유지합니다.
- 카운트다운·날씨 플러그인의 존재하지 않는 타입 경로와 설문 폼의 초기값·제출 타입을 수정했습니다.
- Shop v1.3.2를 연결해 삭제된 상품의 주문 항목에 대한 타입 오류를 해결했습니다. 기존 null 검사와 결제·재고 처리 동작을 유지합니다.
- `npm run typecheck`를 추가하고 Next.js의 타입 오류 무시 설정을 제거했습니다. 타입 검사 대상을 제외하거나 오류를 숨기는 방식으로 해결하지 않았습니다.

## 업데이트 안내

기존 DB와 업로드 파일을 백업하고 로컬 변경을 보존한 다음 main과 서브모듈을 함께 갱신하세요.

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
npm ci
npm run typecheck
npm run build
# Restart the application using your deployment process.
```

- 이 코드 수정에 따른 새 DB 마이그레이션은 없습니다. 기존 메뉴·페이지·위젯·주문 데이터를 초기화할 필요가 없습니다.
- 빌드가 TypeScript 오류를 검사하므로 사용자 추가 코드와 플러그인의 타입 오류도 업데이트 전에 수정해야 합니다.
- 설문 테이블이 누락된 기존 설치에서는 백업 후 `prisma/migrations/0_init/migration.sql`의 해당 테이블 정의를 기준으로 누락분만 보충하세요. dev의 누락된 설문 테이블 4개도 이 방식으로 복구했으며 기존 테이블과 데이터는 유지했습니다. 전체 초기 마이그레이션이나 reset 명령을 재실행하지 않습니다.

## 검증

- 전체 TypeScript 검사 오류 0건, 자동 테스트 81개와 타입 검사를 포함한 프로덕션 빌드를 통과했습니다.
- 별도 DB에서 위젯 초기화 5개 시나리오와 초기 설정 API 요청 7개를 검증했습니다.
- dev API 요청 8개와 브라우저의 설문 초안 작성·수정·새로고침을 확인했습니다. 기존 설정·데이터는 보존하고 검증용 데이터와 별도 DB는 제거했습니다.
